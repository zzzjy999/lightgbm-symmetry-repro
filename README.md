# LightGBM mirror-pair split-search reproduction

[中文说明](README.zh-CN.md)

This repository provides the LightGBM 4.6.0 patch used in the source-code ablation, its recorded build configuration, and a runnable synthetic example. The example shows how a feature rejected at a parent node stays excluded after another feature creates a useful split in its children. The patch removes this inherited exclusion in the serial tree learner.

All input data are generated by `datasets.py`. The package contains no aerodynamic database. The continuous-data check is an additional synthetic validation; it is separate from the aerodynamic results in the paper.

## Version 1.0.1

This release checks all four continuous-data conditions, including the patched library with independent noise. It rejects missing or duplicate conditions, invalid metrics, absent geometry splits in any intervention, and validation error that fails to improve over the clean baseline. Build commands now save stdout, stderr, exit status, and timeout or launch diagnostics before propagating errors.

The update passed 14 unit tests, including fault injection into the previously unchecked condition and the build failure paths. The existing 80 single-tree and four continuous-data results pass the updated 15 checks. This release revalidates those saved results without recompiling or fitting models. The original patch, build settings, data, and numerical results are unchanged. See `expected/revalidated_v1.0.1.json` for the check record.

## Contents

- `patches/parent_feature_reevaluation.patch`: the original experimental patch, copied without alteration.
- `config/build.json`: pinned upstream commit and executable CMake settings.
- `config/original_build.json` and `config/original_*_CMakeCache.txt`: provenance and recorded original build caches, with machine-specific paths replaced by placeholders.
- `scripts/build.py`: exports the pinned upstream sources and builds separate original and patched libraries.
- `datasets.py`: balanced four-cell data, matched noise controls, and continuous synthetic geometries.
- `data/`: CSV snapshots generated by those functions, with seeds and checksums in `data/manifest.json`.
- `reproduce.py`: runs both libraries in separate processes and checks numerical results and geometry splits.
- `expected/`: archived single-tree results and the results of the fresh public-package validation.
- `tests/test_datasets.py`: checks the analytic gains, symmetry, noise matching, and deterministic data generation.
- `tests/test_verification.py` and `tests/test_build_logging.py`: regression tests for complete validation and retained failure diagnostics.

## Build and run

The complete build and verification were tested on Windows x64 with Python 3.12.13, GCC 14.1.0, CMake 4.4.3, Ninja 1.13.2, NumPy 2.4.3, and SciPy 1.17.1. Use a 64-bit MinGW GCC toolchain with OpenMP support. Git, GCC (`gcc`, `g++`), CMake, and Ninja must be on `PATH`. Build requirements are described in the [upstream installation guide](https://lightgbm.readthedocs.io/en/v4.6.0/Installation-Guide.html).

From a terminal in this repository:

```text
python -m venv .venv
```

Activate the environment (PowerShell: `.\.venv\Scripts\Activate.ps1`; a POSIX shell: `source .venv/bin/activate`), then run:

```text
python -m pip install -r requirements.txt -r build-requirements.txt
python scripts/build.py
python -m unittest discover -s tests -v
python reproduce.py
```

The default build downloads the upstream tag and its submodules, verifies the commit and patch checksum, and builds the CPU shared libraries. It does not install or replace your existing LightGBM package. On Windows, `reproduce.py` adds the selected compiler's DLL directory and uses one runtime thread. The Python wrapper comes from the same upstream tag as each native library.

If the executables are not on `PATH`, pass their absolute paths with `--cmake`, `--ninja`, `--cc`, and `--cxx`. To use an existing LightGBM clone with initialized submodules, add `--source <clone-directory>`. The builder exports the pinned Git objects and ignores changes in that clone's working tree. `--jobs 4` controls compilation parallelism, not training threads. The scripts include POSIX build support, but the recorded validation is for Windows.

Existing build and result directories are never overwritten. For another run, choose fresh directories:

```text
python scripts/build.py --work-dir build/second
python reproduce.py --build-manifest build/second/build_manifest.json --output runs/second
```

The full verification performs 80 single-tree fits and four continuous-data fits. A shorter check uses one noise seed:

```text
python reproduce.py --suite smoke --output runs/smoke
```

To export the generated datasets without training:

```text
python datasets.py --output runs/data_only
```

## What the tests check

### Original single-tree experiment

Each dataset contains 128 copies of the four combinations of `beta, z = -1, +1`, with response `y = beta * (a + z)`. The settings use one tree, four leaves, maximum depth two, full row/feature coverage, no regularization, and seeds 11–15. Each library runs two values of `a` and four conditions: clean labels, independent Gaussian noise, odd-symmetric noise matched in RMS, and independent noise with a minimum split gain of `1e-5`.

For consistency with the archived experiment, Gaussian draws have standard deviation `1e-4 * std(y)`; their realized RMS varies slightly by seed. The odd-symmetric control is scaled to the realized RMS of the independent noise.

| Clean task | Original library | Patched library |
| --- | --- | --- |
| `a = 0` (XOR) | No root split; NRMSE = 1 | No root split; NRMSE = 1 |
| `a = 1` | Root splits on beta; 0 geometry splits; NRMSE = 0.707107 | Root splits on beta; 2 geometry splits; NRMSE = 0 |

For `a = 1`, the root beta gain is 512 and each conditional geometry gain is 256. Removing inherited exclusions restores the child splits. For `a = 0`, no profitable initial split exists, so reevaluating child features alone cannot help. These two cases distinguish failure to enter the tree from exclusion after a valid initial split.

NRMSE here is RMSE against clean labels divided by their population standard deviation, evaluated on the four-cell fitting data. All 80 NRMSE values from the fresh build exactly match `expected/archived_single_tree.csv` on the recorded toolchain. The automated tolerance is `1e-10`.

### Additional continuous synthetic validation

For each of 256 independent synthetic geometries, sample five variables uniformly on `[-1, 1]` and evaluate beta at `-1, 0, +1`:

```text
y = beta * (2 + 1.25*sin(pi*z0) + 0.7*z1**2 - 1.1*z2*z3 + 0.45*cos(2*z4))
```

Training and validation use different fixed seeds (20261009 and 20261010), giving 768 rows in each set. Independent label noise uses seed 11 and is scaled to an actual RMS of `1e-4 * std(y_train)`. Models use 300 boosting rounds with the settings in `reproduce.py`. Validation predictions are projected to odd symmetry before NRMSE is calculated using the clean validation-label standard deviation.

| Library and labels | Geometry splits | Validation NRMSE |
| --- | ---: | ---: |
| Original, clean | 0 | 0.396412 |
| Original, independent noise | 8160 | 0.107155 |
| Patched, clean | 8153 | 0.108065 |
| Patched, independent noise | 8160 | 0.107155 |

This dataset checks the mechanism on unseen synthetic geometries. It does not represent CFD outputs or replace the paper's aerodynamic test set.

## Outputs and verification

`build/build_manifest.json` records the resolved build commands, source and native-library hashes, compiler versions, and runtime locations. `build/commands.log` records all build subprocesses; each variant also has `configure.log` and `compile.log`. Successful and failed commands retain both output streams. Timeouts retain partial output, and exceptions identify the log paths. Binary Git archive payloads are omitted from diagnostic logs; their stderr is retained.

`runs/full/` contains generated CSV inputs, per-library logs, result tables, the run protocol, and `verification.json`. A successful full run exits with code zero and reports `status: PASS`, 80 single-tree fits, four continuous fits, and 15 passing checks. Inspect failed assertions and saved logs before rerunning; there is no automatic retry.

The `expected/rebuilt_*` files preserve the original v1.0.0 run and its source hashes. Its verification report contains the earlier nine checks. `expected/revalidated_v1.0.1.json` records the expanded checks against the same results and the updated verifier's hash.

The original patch checksum, original ablation-library checksums, and the newly built library checksums are recorded separately. A native binary rebuilt in another directory or at another time can have a different hash. Numerical checks establish reproduction of the reported behavior; the release does not require byte-identical rebuilt binaries.

## Patch and build details

The upstream tag is `v4.6.0`, commit `d02a01ac6f51d36c9e62388243bcb75c3b1b1774`. The patch changes only the inherited parent-feature exclusion in `SerialTreeLearner::FindBestSplits` in `src/treelearner/serial_tree_learner.cpp`. It leaves the gain calculation and split constraints unchanged. It is the intervention used to test the mechanism, not an upstream LightGBM release.

Both variants use Release CPU builds, the Ninja generator, and OpenMP. GPU, CUDA, MPI, debug mode, and sanitizers are disabled; runtime training uses one thread. The sanitized CMake caches retain the original configuration values and are provenance records, not portable caches to copy into a new build. `config/build.json` is the portable configuration used by the builder.
